# Фото-чипы в описании

**Дата:** 2026-05-26
**Ветка:** `feat/photo-chips`

## Проблема

Оператор пишет описание оффера и хочет сослаться на фото оффера прямо
по позиции: «здесь фото №1, тут текст, дальше фото №2». Сейчас в описании
можно добавить картинку только отдельной секцией (IMAGE-item с URL), и
шаблон описания, привязанный к одному офферу, не годится для другого
(URL картинок другие). Нужно ссылаться на фото по **номеру** — тогда тот же
шаблон описания работает на любом оффере: при публикации `{{photo:1}}` сам
подставляет фото №1 текущего оффера.

## Решение в одной фразе

В тексте описания живёт чип `[ Фото · N ]` — позиционная ссылка на фото
оффера. В редакторе — обычный чип (как переменная). При публикации
разворачивается в реальный IMAGE-item с URL фото из массива оффера.

## Модель данных

| Где | Форма | Пример |
|-----|-------|--------|
| State приложения + шаблон на сервере | токен | `{{photo:1}}` |
| Редактор (contentEditable) | чип-спан | `<span class="var-chip" data-photo-idx="1" contenteditable="false">Фото · 1</span>` |
| Публикация на Allegro | IMAGE-item | `{ type: 'IMAGE', url: photoUrls[0] }` |

`N` — 1-based позиция в массиве фото оффера. Хранится в `data-photo-idx`.
Стиль чипа повторяет переменную (`var-chip`), `var-chip--missing` —
когда у оффера нет фото с таким номером.

## Различение токенов

`{{photo:N}}` отличается от переменной-токена двоеточием. Имена параметров
Allegro двоеточий не содержат — конфликта нет.

Утилиты в `web/src/components/shortcodes.ts` (`tokensToChipsHtml`,
`chipsHtmlToTokens`, `chipHtml`) расширяются: смотрят, начинается ли ключ
с `photo:`, и рисуют соответствующий чип. Внешний API утилит не меняется
для существующих вызовов.

## UI

В тулбар `RichTextarea` рядом с **«+ Переменная»** появляется
**«+ Фото»**. Клик открывает выпадашку с миниатюрами всех текущих фото
оффера + номер (1, 2, 3…). Клик по миниатюре вставляет `{{photo:N}}` в
позицию курсора (через `execCommand('insertHTML')`, как переменная).

Кнопка задизейблена, если у оффера нет фото. Закрытие меню — по клику вне
(тот же паттерн что у пикера переменных).

Лайв-обновление: при изменении списка фото оффера (добавил/убрал/переставил)
все чипы в редакторе пересчитывают своё missing/ok-состояние без полного
перерендера innerHTML (как уже сделано для `varMap`).

## Раскрытие чипов при публикации

Новая чистая функция `expandPhotoChips(description, photoUrls)` в
`shortcodes.ts`:

- Для каждого TEXT-item: сканирует токены `{{photo:N}}`, режет контент на
  куски, собирает последовательность items в той же секции:
  `TEXT "до" + IMAGE photoUrls[N-1] + TEXT "после"`.
- Пустые TEXT-куски выкидываются.
- Если `N > photoUrls.length` или `N < 1` — токен остаётся в тексте как
  есть, ключ попадает в `unresolved: string[]`.
- IMAGE-item-ы не трогаются.

Возвращает `{ sections, unresolved }` — тот же контракт, что у `flattenVars`.

Порядок в `buildPayload`:

```
description.sections
    │
    ├── strip empty TEXT/IMAGE-items (existing)
    │
    ├── flattenVars(..., varMap)       ← переменные → значения (existing)
    │
    └── expandPhotoChips(..., photoUrls) ← фото-чипы → IMAGE-items (new)
            │
            └── payload.descriptionOverride
```

## Проводка

- `RichTextarea` получает доп. опциональный проп `photoUrls?: string[]`.
- `DescriptionEditor` пробрасывает его дальше; добавляется опциональный проп.
- `App.tsx` передаёт текущий `imageUrls` (state клон-потока).
- `NewProductPanel` передаёт `images` (state создания товара).
- `buildPayload` в обоих местах добавляет `expandPhotoChips(...)` после
  `flattenVars(...)`.

`photoUrls` — опциональный, чтобы консьюмеры без фото не ломались
(дефолт — пустой массив).

## Поведение шаблонов

Существующая фича шаблонов описания не меняется. Поскольку чипы хранятся
как `{{photo:N}}` — переносимы между офферами автоматически: применяешь
шаблон с фото-чипами к другому офферу, чипы пересчитываются под фото этого
оффера. Тот же оператор-флоу, что и с переменными.

## Тесты

- `shortcodes.test.ts`:
  - `expandPhotoChips`: одиночный чип, несколько чипов в одном TEXT, чипы
    по краям (в начале/конце), missing index → токен остаётся + key в
    unresolved, IMAGE-items не модифицируются, пустые TEXT-куски
    выкидываются.
  - `tokensToChipsHtml` / `chipsHtmlToTokens`: round-trip фото-чипа,
    различение `{{photo:N}}` vs `{{Variable}}`.

Тесты UI (пикер, миниатюры) — ручная проверка в браузере.

## Вне scope (YAGNI)

- Серверного хранилища нет — фото-чип это позиционная ссылка.
- Drag-n-drop чипов между секциями: нет.
- Превью фото-миниатюрой внутри чипа (вместо текста «Фото · N»): нет.
  Можно добавить позже, если будет нужно.
- Именованные фото (а не по номеру): нет — спека про номера.
