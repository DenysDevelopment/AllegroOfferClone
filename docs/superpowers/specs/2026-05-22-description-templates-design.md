# Шаблоны описания с переменными-чипами

**Дата:** 2026-05-22
**Ветка:** `feat/description-templates`

## Проблема

Оператор клонирует офферы Allegro и каждый раз заново собирает описание из секций.
Нужно:

1. Сохранять описание целиком как именованный **шаблон** и применять его к другим
   офферам.
2. **Переменные** (шорткоды) внутри текста описания, которые подставляют значения
   параметров текущего оффера — чтобы один шаблон подходил под разные офферы.

## Ключевая модель: переменная = чип

В редакторе описания переменная отображается **не** как `{{...}}`, а как **чип**
(плашка): `[ SSD · 512 GB ]` — видно одновременно **и ключ, и значение**.

Чип ведёт себя как один неделимый символ:

- `contenteditable="false"` — курсор внутрь не заходит;
- Backspace/Delete удаляют чип целиком;
- значение в чипе «живое» — всегда отражает актуальный параметр текущего оффера
  (с учётом операторских оверрайдов).

### Три представления одних данных

| Где | Форма | Пример |
|-----|-------|--------|
| Редактор (contentEditable) | чип-спан | `<span class="var-chip" data-var="SSD" contenteditable="false">SSD · 512 GB</span>` |
| State приложения + шаблон на сервере | токен | `{{SSD}}` |
| Публикация на Allegro | готовое значение | `512 GB` |

`RichTextarea` при получении `value` парсит `{{key}}` → рисует чипы; при `emit`
сериализует чипы обратно в `{{key}}`. Снаружи компонент всегда работает с
токен-формой `{{key}}` — остальное приложение про чипы не знает.

### Тайминг подстановки

Переменные остаются **живыми чипами всё время редактирования** (чип сам показывает
значение). В плоский текст они «схлопываются» только при отправке оффера на Allegro.
Так ключ и значение видны постоянно, а шаблон остаётся переносимым между офферами.

## Переменные

- **Параметры оффера** — по имени параметра: `{{Pojemność dysku SSD}}`.
- **Встроенные поля оффера** — с префиксом `@`, чтобы не конфликтовать с именами
  параметров: `{{@title}}` (название оффера), `{{@price}}` (цена).
- **Резолв значения:** операторский оверрайд параметра имеет приоритет над исходным
  значением. Если оверрайда нет — берётся `paramDisplayValue` исходного параметра.
- **Нерезолвленный ключ** (параметра нет на целевом оффере): чип рисуется
  «тревожным» стилем — показывает только ключ, без значения. После применения
  шаблона выводится список таких ключей, чтобы оператор поправил вручную.
- **Экранирование:** подставляемое значение HTML-экранируется (значение параметра —
  это текст, не разметка), чтобы не сломать HTML описания.

## Архитектура

### Сервер

**`server/src/core/templates.ts`** — новый модуль `TemplateStore`:

- Файл `data/description-templates.json` — единый массив шаблонов, глобальный для
  всех аккаунтов.
- Атомарная запись (`.tmp` + `rename`) по образцу `TokenStore`.
- Методы: `list()`, `create(name, sections)`, `update(id, patch)`, `remove(id)`.

Тип шаблона:

```ts
interface DescriptionTemplate {
  id: string;          // crypto.randomUUID()
  name: string;
  sections: DescriptionSections['sections']; // в токен-форме {{key}}
  createdAt: number;   // epoch ms
  updatedAt: number;
}
```

**`server/src/routes/api.ts`** — новые роуты (`TemplateStore` создаётся один раз
при инициализации роутера, не зависит от аккаунта):

- `GET    /api/description-templates` → `{ templates: DescriptionTemplate[] }`
- `POST   /api/description-templates` → body `{ name, sections }` → созданный шаблон
- `PUT    /api/description-templates/:id` → body `{ name?, sections? }` → обновлённый
- `DELETE /api/description-templates/:id` → `204`

Валидация: переиспользовать `descriptionSchema` для `sections`,
`name: z.string().min(1).max(100)`.

### Клиент

**`web/src/api.ts`** — тип `DescriptionTemplate` + объект `descriptionTemplates` с
методами `list / create / update / remove`.

**Чистые утилиты** (`web/src/components/shortcodes.ts` — новый файл):

- `buildVarMap(preview, overrides)` → `Map<key, value>` — карта переменных:
  параметры оффера (с учётом оверрайдов) + `@title` / `@price`.
- `tokensToChipsHtml(html, varMap)` → HTML с чип-спанами (для отрисовки в редакторе).
- `chipsHtmlToTokens(html)` → HTML с `{{key}}` (для emit / сохранения).
- `flattenVars(sections, varMap)` → `DescriptionSections` с подставленными
  значениями (для публикации). Возвращает также список нерезолвленных ключей.

**`web/src/components/DescriptionEditor.tsx`**:

- В шапку панели «Описание» добавляется блок **«Шаблоны»**:
  - **Сохранить как шаблон** — запрос имени, POST текущего описания (в токен-форме).
  - **Применить шаблон** — список шаблонов; при выборе спросить «заменить секции» /
    «добавить секции»; затем подставить в state.
  - **Управление** — переименование / удаление.
- `RichTextarea` получает `varMap` (проп), рендерит `{{key}}` как чипы.
- В тулбар `RichTextarea` — кнопка **«+ Переменная»**: дропдаун со списком
  параметров текущего оффера + встроенными полями; выбор вставляет чип в позицию
  курсора. Ручной ввод `{{...}}` тоже превращается в чип (при emit/blur).

**`web/src/App.tsx`**:

- Загружает список шаблонов при наличии `preview`.
- Передаёт `DescriptionEditor` карту переменных (`buildVarMap(preview, overrides)`).
- При сборке clone-payload прогоняет `description` через `flattenVars` — Allegro
  получает плоский текст без токенов.

## Поток данных

```
Загрузка оффера → preview + parameters
       │
       ├── buildVarMap(preview, overrides) ──► varMap
       │
DescriptionEditor (state в токен-форме {{key}})
       │   RichTextarea рисует чипы через varMap
       │
       ├── «Сохранить как шаблон» → POST /api/description-templates (токен-форма)
       ├── «Применить шаблон»     → GET шаблон → setDescription (токен-форма)
       │
clone-payload → flattenVars(description, varMap) → плоский текст → Allegro
```

## Вне scope (YAGNI)

- Вложенные шаблоны (шаблон внутри шаблона).
- Шаблоны на отдельную секцию (только описание целиком).
- Папки / категории шаблонов.
- Шаблоны на конкретный аккаунт (хранилище глобальное).
- Живой предпросмотр с переключателем (чип и так показывает значение).
