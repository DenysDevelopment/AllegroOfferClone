# Клон: заголовок из каталога + раскладки строк описания

**Дата:** 2026-05-28
**Ветка:** `feat/clone-title-and-description-layout`

## Проблема

Две жалобы оператора на текущий клон оферты:

1. **Заголовок.** По умолчанию title клона берётся из названия *оферты* (`preview.name`).
   Нужно брать название *карточки товара из каталога* Allegro (`preview.product.name`).
2. **Описание «разваливается».** При сборке тела описание прогоняется через
   `splitDescriptionSectionsToMaxTwoItems`, который слепо бьёт элементы секции по
   парам и иногда склеивает два текстовых блока в одну строку `[TEXT, TEXT]` —
   запрещённую Allegro комбинацию. Плюс редактор не даёт детерминированно собирать
   «красивые» строки (текст слева + фото справа, два фото рядом).

## Правила Allegro по описанию (подтверждено документацией)

Описание — это набор **строк** (секций). Каждая строка содержит 1–2 элемента
(`items`) типа `TEXT` или `IMAGE`. Допустимы **ровно 5 раскладок**:

| Раскладка | items |
|-----------|-------|
| Только текст | `[TEXT]` |
| Только фото | `[IMAGE]` |
| Текст + фото (текст слева, фото справа) | `[TEXT, IMAGE]` |
| Фото + текст (фото слева, текст справа) | `[IMAGE, TEXT]` |
| Два фото рядом | `[IMAGE, IMAGE]` |

Запрещена единственная двухэлементная комбинация — **`[TEXT, TEXT]`** (два текста в
одной строке). Источники: [Allegro — How to create the product description](https://help.allegro.com/en/sell/a/how-to-create-the-product-description-nnker5OPPH9),
[ChannelEngine — Allegro marketplace guide](https://support.channelengine.com/hc/en-us/articles/4409503063069-Allegro-marketplace-guide),
[allegro/convert-description](https://github.com/allegro/convert-description).

## Решение — 4 части

### 1. Title клона — из карточки каталога

**Клиент (`web/src/App.tsx`).** `autoName` больше не подставляет оверрайды
параметров и берёт за основу название карточки каталога:

```ts
const autoName = preview?.product?.name ?? preview?.name ?? '';
```

- Цикл `substituteValueVariants` по оверрайдам из расчёта `autoName` удаляется
  (`overrides` больше не в зависимостях этого `useMemo`).
- Поле title остаётся редактируемым вручную (`nameUserEdited` гасит авто-заполнение).
- Поведение при target-bind не меняется: name берётся из карточки (как сейчас),
  авто-заполнение пропускается.
- `@title`-переменная в `buildVarMap` по-прежнему мапится на `nameOverride` (текущее
  значение поля) — это не трогаем.

**Сервер (`server/src/core/clone.ts`).** Дефолт `newName` (ветка без
`options.nameOverride`) меняем с `rewriteTitle(source.name ...)` на название
карточки каталога без подстановки:

```ts
const newName = options.nameOverride ?? productName ?? source.name ?? '';
```

`productName` уже вычисляется выше (из `sourceProduct.name` / `full.name`). Это
страховка для прямых вызовов API и dry-run; UI всё равно присылает `nameOverride`.
Шаг лога «Название: …» сохраняется.

### 2. Сервер — безопасная сеть разбивки секций

`splitDescriptionSectionsToMaxTwoItems` (в `server/src/core/clone.ts`)
дорабатывается так, чтобы **каждая** выходная секция была валидной раскладкой:

- секция с >2 items → режется по 2, сохраняя порядок (как сейчас);
- **новое:** двухэлементная пара `[TEXT, TEXT]` разбивается на две односекционные
  строки `[TEXT]` + `[TEXT]`;
- валидные комбинации (`[TEXT]`, `[IMAGE]`, `[IMAGE,IMAGE]`, `[TEXT,IMAGE]`,
  `[IMAGE,TEXT]`) не трогаются.

Реализация: после нарезки по 2 пройтись по результату и для каждой пары проверить —
если оба элемента `TEXT`, заменить её на две односекционные. Шаг лога обновляется
(сообщать о числе расщеплённых текст-пар). Функция остаётся в пайплайне `cloneOffer`,
который применяется и к `proposeProduct`.

**Валидация (`server/src/core/body-validate.ts`).** Добавить правило уровня `error`:
секция из двух `TEXT` невалидна — `description.sections[i]: два TEXT-элемента в одной
строке запрещены Allegro`. Это диагностика до отправки (раскладка из редактора такого
не создаёт, но прямой API/легаси-данные могут).

### 3. Редактор — строка = раскладка (`web/src/components/DescriptionEditor.tsx`)

Каждая секция отображается как **строка с селектором раскладки** (5 вариантов из
таблицы выше).

**Чистый хелпер в новом модуле `web/src/components/descriptionLayout.ts`** (по
образцу `shortcodes.ts` — чистые утилиты отдельно от компонента ради тестируемости):
`detectLayout(items): Layout` и `relayoutSection(items, layout): DescriptionItem[]`,
где `type Layout = 'text' | 'image' | 'text-image' | 'image-text' | 'image-image'`:

- детектит текущую раскладку из формы `items` (для секций, пришедших из источника /
  шаблона): `[TEXT]`→`text`, `[IMAGE]`→`image`, `[TEXT,IMAGE]`→`text-image`,
  `[IMAGE,TEXT]`→`image-text`, `[IMAGE,IMAGE]`→`image-image`;
- при смене раскладки переформирует `items`, **сохраняя контент по позиции**:
  - недостающие элементы создаются пустыми: `{type:'TEXT',content:''}` /
    `{type:'IMAGE',url:''}`;
  - лишние элементы отбрасываются;
  - существующий TEXT-контент и IMAGE-url переносятся в слот того же типа, если он
    есть в новой раскладке (по индексу, затем по совпадению типа).

**Рендер строки:**

- заголовок строки: «Строка N», селектор раскладки (`<select>` или компактный
  дропдаун), кнопки `↑ ↓ ✕` (как сейчас);
- 1-элементные раскладки — слот на полную ширину (как сейчас);
- 2-элементные — `grid grid-cols-2 gap-2`, два слота бок о бок (зеркалит Allegro);
- слот TEXT — существующий `RichTextarea` (чипы/переменные/фото-пикер сохраняются);
- слот IMAGE — существующий блок «превью + input URL + `PhotoPicker`» (+ поддержка
  `{{photo:N}}` photo-ref, как сейчас).

**Кнопки:**

- внутренние «+ текст / + картинка» в секции **убираются** (состав задаётся
  раскладкой);
- внизу «+ строка» с выпадающим выбором стартовой раскладки (Текст / Фото /
  Текст+Фото / Фото+Текст / Два фото);
- `reset`, `dirty`, перемещение, удаление секции, меню «Шаблоны» — без изменений.

Сигнатура пропсов `DescriptionEditor` и внешний контракт `onChange(DescriptionSections)`
не меняются — наружу по-прежнему отдаются `sections` в токен-форме.

### 4. Совместимость и тесты

**Совместимость.** Существующие описания и шаблоны состоят из валидных секций;
детект раскладки покрывает все 5 форм, поэтому открываются корректно. Токен-форма
переменных (`{{key}}`, `{{photo:N}}`) и round-trip чипов не затрагиваются.

**Тесты:**

- `server/src/core/clone.test.ts` — `splitDescriptionSectionsToMaxTwoItems`:
  `[TEXT,TEXT]` → 2 секции `[TEXT]`+`[TEXT]`; `[TEXT,IMAGE,TEXT]` →
  `[TEXT,IMAGE]`+`[TEXT]`; `[IMAGE,IMAGE]` и `[TEXT,IMAGE]` не меняются; >2 items
  режутся по 2 и затем чинятся от текст-пар.
- `server/src/core/clone.test.ts` (или существующий title-тест) — `buildCloneBody`
  без `nameOverride` берёт `productName` карточки, а не `source.name`.
- новый `server/src/core/body-validate.test.ts` — ошибка на секции `[TEXT,TEXT]`,
  валидные раскладки проходят.
- новый `web/src/components/descriptionLayout.test.ts` — `detectLayout` на каждой из
  5 форм + `relayoutSection` с сохранением контента (text→text-image создаёт пустой
  IMAGE и сохраняет TEXT; image-image→text отбрасывает второй IMAGE и т.д.).

## Вне scope (YAGNI)

- Перетаскивание (drag-and-drop) строк — оставляем `↑ ↓`.
- Произвольная ширина колонок / >2 элементов в строке — Allegro не поддерживает.
- «Умная» авто-упаковка свободного списка элементов в красивые строки — раскладку
  теперь задаёт оператор явно; сервер лишь гарантирует валидность.
- Изменение формата хранения шаблонов/описания — структура `sections[].items[]`
  остаётся прежней.
